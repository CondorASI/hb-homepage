# HB homepage showcase

Standalone, single-page showcase of a new homepage for Hauptmeijer-Beilschmidt (HB, h-b.nu): a repositioning from "HR services provider" to "strategic consultancy for owner-led organisations". Built with Astro (static output) and Tailwind CSS v4.

## Run

Requires Node.js 20 or newer.

```bash
npm install
npm run dev        # http://localhost:4321
```

## Build

```bash
npm run build      # writes a deployable static site to dist/
npm run preview    # serves dist/ locally
```

`dist/` is plain HTML, one inlined stylesheet, five self-hosted Manrope font files and the images. Upload it to any static host, or open `dist/index.html` directly in a browser to preview it without a server.

## Verify (the quality bar from the brief)

```bash
npm run screenshots   # full-page captures at 375 / 768 / 1440 px into screenshots/, plus overflow, tap-target and no-JS checks
npm run lighthouse    # Lighthouse mobile + desktop against dist/ (uses the Chromium that Playwright installs)
```

Both scripts need `npm run build` first and, once, `npx playwright install chromium`.

## Where to put real images and logos

- `public/images/source/` holds the **untouched originals** downloaded from h-b.nu (photos, `favicon.svg`, `HB_Beeldmerk_wit.png`, `logos/`, and the five small YOOtheme-resized session photos in `sessions/`). Nothing in this folder is served directly.
- `scripts/images.mjs` turns those originals into the slot files the page uses (`public/images/hero.webp`, `hero@2x.webp`, `team.webp`, `team@2x.webp`, `aanpak.webp`, `aanpak-sm.webp`, `case.webp`, `instrument.webp`, `instrument@2x.webp`, `og.jpg`, `logo-white.png`, `logos/<name>.webp` + `@2x`). It crops with sharp (`fit: cover`, `position: attention`).
- To swap a photo: drop the new original into `public/images/source/`, point the matching entry in `scripts/images.mjs` at it, run `npm run images`, rebuild.
- To swap or add a client logo: put the file in `public/images/source/logos/`, add its name to the `logos` array in `scripts/images.mjs` **and** to the list in `src/components/LogoStrip.astro` (with the 1x width the script prints), run `npm run images`.
- The header logo is `public/images/logo.svg` (the site's `favicon.svg`, run through svgo; the Adobe wrapper was removed).

## Project layout

```
src/pages/index.astro         the page: one component per section
src/components/*.astro        Header, Hero, LogoStrip, Advies, Aanpak, Bewijs, Assessments, VoorWie, OverHB, Abonnement, Inzichten, Contact, Footer (+ SectionHeading helper)
src/layouts/Base.astro        <head>, meta/OG tags, skip link
src/styles/global.css         design tokens (@theme) + base + component classes (.btn, .card, .eyebrow, .container-hb, .section)
scripts/                      images.mjs, screenshots.mjs, lighthouse.mjs, serve.mjs (tiny static server used by the checks)
public/images/                generated slot files; source/ = originals
screenshots/                  latest captures (375, 768, 1440, 375 with open menu, 1440 with JS disabled)
```

## Design decisions beyond the brief

- **Green text token darkened.** The brief's `accent-dark` (`#5F8F22`) is only 3.86:1 on white, which fails AA for small text. It is now `#4A7118` (≥ 5.2:1 on every light surface). The bright `accent` green is used only for buttons (with dark text) and decorative markers, never for text on light backgrounds. Every text/background pair was checked with a small contrast script; all pass 4.5:1.
- **Section rhythm.** Hero warm off-white → logos white → Advies tint → Aanpak white → Bewijs white (bordered cards carry the structure) → Assessments tint → Voor wie white → Over HB warm → subscription strip tint → Inzichten white → Contact dark purple → footer darker purple. The brief asked for the assessments block to be tinted and only one dark section; the rest follows from that.
- **Aanpak layout.** Heading and intro sit beside the group photo; the three numbered steps run in a row underneath. The photo only exists at 800 px, so it is never shown wider than ~560 px on desktop and is never upscaled.
- **Assessments block.** Photo on the left, text on the right on desktop; on phones the text comes first and the photo follows.
- **Placeholders are visible.** Unknown statistics render as a large grey em dash; Krista's and Henk's surnames render literally as `[achternaam]`; `KvK [nummer]` stays in the footer. See `CONTENT-TODO.md` for the full list.
- **Plain `<img srcset>` instead of Astro's `<Image>`.** The slot files are pre-generated by `scripts/images.mjs`, so the client can inspect exactly what is served and the build does no image processing. Client logos use 1x/2x density descriptors; photos use width descriptors with `sizes`.
- **Performance choices.** The single ~30 kB stylesheet is inlined (it was the only render-blocking request); the hero image has `fetchpriority="high"`, everything below the fold is `loading="lazy"`.
- **Relative asset paths.** All image and font URLs are relative (`images/…`, `_astro/…`) and a tiny build hook in `astro.config.mjs` rewrites the font URLs the same way, so `dist/index.html` also works when opened straight from disk (double-click), not only from a web server. Deploy `dist/` at the site root or any subfolder.
- **JavaScript.** One small module: the mobile menu toggle (with `aria-expanded`, Escape to close) and an `IntersectionObserver` on a 1 px sentinel that adds the header's bottom border once the page is scrolled. Nothing on the page depends on JS: with scripts disabled every section and image renders on first paint (verified by `npm run screenshots`).
- **Article cards** use a "stretched link" on the title so the whole card is clickable while there is only one link per card for assistive tech; the "Lees verder →" text is decorative.
- **`NL / EN` switch** is shown as a disabled placeholder in the desktop nav, as the brief allowed.
- **Smooth in-page scrolling** with `scroll-padding-top` for the sticky header; disabled under `prefers-reduced-motion`, as are all transitions.
- **Footer description** avoids inventing a founding year ("Ruim 30 jaar gevestigd in Den Haag").
